# PagesCMS 适配配置项规划

> 状态：规划稿，仅记录可配置项和约束。
>
> 本文不包含 PagesCMS 配置文件，也不会直接修改博客的数据结构或构建流程。正式适配前需要先确认首期范围，并据此实现 `.pages.yml` 及必要的数据层调整。

## 1. 当前项目内容结构

| 内容 | 当前路径 | 当前格式 | 备注 |
| --- | --- | --- | --- |
| 博客文章 | `src/content/posts/` | `.md` / `.mdx` | 已有 Astro Content Collection，字段由 `src/content.config.ts` 定义 |
| 特殊页面正文 | `src/content/spec/` | `.md` / `.mdx` | 当前包含 `about.md`、`friends.mdx`、`guestbook.md` |
| 友链数据 | `src/config/friendsConfig.ts` | TypeScript 数组 | 目前不能直接作为普通 CMS 数据文件编辑 |
| 相册元数据 | `src/config/galleryConfig.ts` | TypeScript 数组 | 相册 ID 必须与 `public/gallery/<id>/` 目录一致 |
| 相册图片 | `public/gallery/<id>/` | 图片、`urls.txt` | 本地图片和远程图片 URL 均可存在 |
| 站点及主题配置 | `src/config/*.ts` | TypeScript | 会影响构建和运行行为，建议与内容编辑分开管理 |

## 2. 首期建议开放的内容

首期建议只开放以下内容，保持改动范围小、回滚简单：

1. 文章创建、编辑、发布和媒体上传。
2. 关于页、友链页说明、留言板说明等 Markdown 正文。
3. 友链条目（需要先把当前 TypeScript 数组迁移为 YAML/JSON/Markdown 数据文件）。
4. 相册元数据和相册目录中的图片（需要保证相册 ID 与目录名一致）。

以下内容首期不建议开放：

- 评论系统、统计服务、API Key、TMDB 等密钥或任何环境变量。
- `astro.config.mjs`、`wrangler.jsonc`、`vercel.json` 等部署配置。
- 侧边栏组件顺序、Markdown/MDX 插件、代码高亮和加密实现。
- 由构建脚本生成的字段，以及会改变路由规则的字段。

## 3. 文章集合（`src/content/posts/`）

### 3.1 建议在 CMS 中显示的字段

| 字段 | 类型/控件 | 必填 | 默认值 | 说明 |
| --- | --- | ---: | --- | --- |
| `title` | 单行文本 | 是 | — | 文章标题 |
| `published` | 日期时间 | 是 | — | 发布时间；用于列表和归档排序 |
| `updated` | 日期时间 | 否 | `published` | 最后更新时间；为空时由 schema 回退到发布时间 |
| `draft` | 开关 | 否 | `false` | 草稿在生产环境不展示 |
| `description` | 多行文本 | 否 | `""` | 列表卡片和 SEO 描述 |
| `image` | 图片/文本 | 否 | `""` | 支持相对路径或远程 URL；文章中的本地图片建议使用相对路径 |
| `color` | 单行文本 | 否 | `""` | 文章主题色，当前使用 CSS 颜色值（例如 `hsl(...)`） |
| `tags` | 字符串列表 | 否 | `[]` | 文章标签 |
| `category` | 单行文本或可选下拉 | 否 | `""` | 文章分类；需要时可改为预设分类列表 |
| `lang` | 下拉/单行文本 | 否 | `""` | 文章语言代码，如 `zh_CN`、`en` |
| `pinned` | 开关 | 否 | `false` | 是否置顶 |
| `author` | 单行文本 | 否 | `""` | 作者名称 |
| `sourceLink` | URL | 否 | `""` | 原文或来源链接 |
| `licenseName` | 单行文本 | 否 | `""` | 文章许可证名称 |
| `licenseUrl` | URL | 否 | `""` | 许可证地址 |
| `comment` | 开关 | 否 | `true` | 是否显示文章评论区 |
| `password` | 密码/单行文本 | 否 | `""` | 加密文章密码；提交到 Git 前必须确认仓库权限和安全风险 |
| `passwordHint` | 单行文本 | 否 | `""` | 密码提示 |
| `ai` | 多行文本（或布尔+文本） | 否 | `""` | AI 总结；当前 schema 同时接受字符串和布尔值，建议 CMS 首期只提供文本输入 |
| `body` | Markdown 编辑器 | 是 | — | 文章正文 |

### 3.2 不应作为 CMS 字段的内容

- `prevTitle`、`prevSlug`、`nextTitle`、`nextSlug`：由文章排序逻辑在运行时计算。
- `slug`：仓库中个别文章已经出现该字段，但当前 `postSchema` 没有声明它，路由实际使用文件 ID。首期建议继续使用文件名作为 URL 标识；如果要开放 slug，必须先同步修改 schema、路由和冲突校验。
- 任何构建产物、缓存字段或自动生成的摘要字段。

### 3.3 文件和格式建议

- 新建文章默认使用 `.md`；现有 `.mdx` 文章保留，但不建议在 CMS 中允许普通编辑者随意创建 MDX。
- 文件名应作为稳定 ID，建议使用小写英文、数字和连字符，避免中文文件名、空格和重复 slug。
- `published` 使用带时区的 ISO 日期时间，避免不同构建环境产生日期偏差。
- `image` 如果引用文章目录中的图片，建议使用类似 `./images/cover.avif` 的相对路径；远程图片可直接填写 URL。

## 4. 特殊页面正文（`src/content/spec/`）

### 4.1 页面列表

| 文件 | 用途 | CMS 编辑内容 |
| --- | --- | --- |
| `about.md` | 关于页正文 | Markdown 正文 |
| `friends.mdx` | 友链页底部的自定义说明/申请说明 | Markdown 正文；如没有 JSX 需求，建议后续改为 `.md` |
| `guestbook.md` | 留言板说明文字 | Markdown 正文 |

这些页面的标题和描述目前主要由 i18n 和页面配置提供，不建议把 `title`、`description` 当作首期必填字段。当前 `spec` 集合的 schema 是空对象；如果需要在 CMS 中维护 frontmatter，适配时必须先补充对应 schema，否则字段可能不会进入类型数据。

## 5. 友链配置项（后续开放）

当前友链保存在 `src/config/friendsConfig.ts`，PagesCMS 更适合编辑 YAML/JSON 或独立 Markdown 集合。因此建议先迁移数据格式，再接入 CMS。

### 5.1 友链条目字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | ---: | --- |
| `title` | 单行文本 | 是 | 站点名称 |
| `imgurl` | 图片/URL | 是 | 站点头像或 Logo |
| `desc` | 多行文本 | 是 | 站点简介 |
| `siteurl` | URL | 是 | 站点地址 |
| `tags` | 字符串列表 | 否 | 用于页面筛选 |
| `weight` | 数字 | 是 | 数字越大排序越靠前 |
| `enabled` | 开关 | 是 | 是否在页面展示 |
| `issue_id` | 数字 | 否 | 自动申请流程对应的 Issue 编号；普通编辑者可隐藏 |

### 5.2 友链页面选项

这些选项当前位于 `friendsPageConfig`：

- `title`：页面标题，为空时使用翻译文本。
- `description`：页面描述，为空时使用翻译文本。
- `showCustomContent`：是否展示 `friends.mdx` 的自定义内容。
- `showComment`：是否展示评论区，前提是评论系统已启用。
- `randomizeSort`：是否随机排序；开启后忽略 `weight`。

## 6. 相册配置项（后续开放）

当前相册元数据位于 `src/config/galleryConfig.ts`，照片位于 `public/gallery/<album-id>/`。建议把每个相册做成一个可编辑条目，同时保留目录名校验。

### 6.1 相册元数据字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | ---: | --- |
| `id` | 单行文本 | 是 | URL slug，同时必须对应 `public/gallery/<id>/` 目录名；创建后不建议修改 |
| `name` | 单行文本 | 是 | 相册名称 |
| `description` | 多行文本 | 否 | 相册描述 |
| `location` | 单行文本 | 否 | 地点或作品来源 |
| `date` | 日期 | 否 | 相册日期 |
| `tags` | 字符串列表 | 否 | 相册标签 |
| `cover` | 图片/URL | 否 | 手动指定封面；为空时自动寻找 `cover.*` 或第一张图片 |
| `password` | 密码/单行文本 | 否 | 相册访问密码；同样需要评估明文存储风险 |
| `passwordHint` | 单行文本 | 否 | 密码提示 |

### 6.2 相册媒体约定

- 本地图片放在 `public/gallery/<id>/`。
- 命名为 `cover.avif`、`cover.webp` 等的文件会优先作为封面。
- `urls.txt` 可用于追加远程图片 URL，每行一个 URL，`#` 开头的行视为注释。
- `networkAlbum`（网络随机图 API、分类、数量和冷却时间）属于功能配置，不建议交给首期 CMS 编辑。

## 7. 站点与主题设置（可选的第二阶段）

这些选项目前分散在 TypeScript 配置文件中，修改后通常需要重新构建。可以列入 PagesCMS 规划，但不建议和文章编辑一起开放。

| 配置模块 | 可配置内容 | 风险/备注 |
| --- | --- | --- |
| 站点基础信息 | 标题、副标题、站点 URL、描述、关键词、语言、建站日期、时区 | 站点 URL 和语言会影响 RSS、SEO 与路由 |
| 主题色与布局 | 色相、默认明暗模式、是否固定主题色、页面宽度 | 主题色需要限制数值范围 |
| Favicon 与导航栏 | 图标、导航标题、全宽/吸顶开关、链接预设 | URL 和图标名称需要校验 |
| 页面开关 | 友链、打赏、留言板、番组计划、相册、追番 | 关闭页面会同步影响导航入口 |
| 文章列表 | 列表/网格、移动端模式、标签/摘要显示、瀑布流、列数 | 属于站点级视觉设置 |
| 文章详情页 | Callout 主题、编辑时间卡片、过期阈值、分享海报、OG 图片 | OG 图片生成可能显著增加构建时间 |
| 分页与图片优化 | 每页文章数、输出格式、压缩质量、防盗链域名 | 影响构建耗时和外部图片加载 |
| 个人资料 | 头像、名称、简介、社交链接 | 头像涉及 `src/assets` 与 `public` 两种路径规则 |
| 公告 | 标题、内容、可关闭、链接 | 内容可开放，链接类型需校验 |
| 侧边栏 | 启用状态、左右位置、组件顺序、显示条件 | 结构复杂，建议先保留代码配置 |
| 评论/统计/字体 | Twikoo、Waline、Giscus、Umami、字体等 | 可能包含密钥、域名和外部服务配置，不应默认开放 |
| 打赏 | 收款方式、二维码、链接、打赏者列表 | 二维码和个人信息需要权限控制 |

## 8. 媒体库规划

建议在 PagesCMS 中至少拆分以下媒体入口：

| 媒体入口 | 目标目录 | 使用场景 |
| --- | --- | --- |
| 文章图片 | `src/content/posts/images/`（或文章目录下的 `images/`） | 文章正文和 `image` 字段 |
| 相册图片 | `public/gallery/` 下按相册 ID 分目录 | 相册照片、封面 |
| 站点公共图片 | `src/assets/images/` 或 `public/assets/images/` | 头像、Logo、广告、打赏二维码 |

适配时需要统一 `image` 字段的输出路径规则，避免 CMS 上传后生成的路径与 Astro 的 `src`/`public` 处理方式不一致。

## 9. 适配前需要确认的决策

1. 首期是否只管理文章和 Markdown 页面，还是同时迁移友链、相册数据。
2. 文章是否允许创建 `.mdx`，以及是否开放 `password`、`ai` 这类高级字段。
3. 是否接受将 `friendsConfig.ts`、`galleryConfig.ts` 迁移为 YAML/JSON 数据文件。
4. `slug` 是否继续由文件名决定；如果需要独立 slug，应先完成 schema 与路由设计。
5. CMS 媒体上传统一放入 `src` 还是 `public`，以及远程图片 URL 是否允许。
6. 是否允许编辑站点级 TypeScript 配置；建议默认不允许，仅在后续建立安全的数据文件后开放。

## 10. 建议的实施顺序（下一阶段）

1. 确认第 9 节决策，冻结首期字段。
2. 为文章集合编写 PagesCMS collection 配置，并先只支持 Markdown。
3. 配置文章图片媒体入口，验证相对路径、远程 URL 和构建结果。
4. 为 `spec` 集合补充明确 schema，再接入三个特殊页面正文。
5. 如有需要，将友链和相册元数据迁移为 CMS 友好的数据文件。
6. 最后再评估站点设置、侧边栏和第三方服务配置是否值得开放。
